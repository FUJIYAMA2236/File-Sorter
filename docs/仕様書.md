## 1. 概要

ダウンロードフォルダ（または任意の監視フォルダ）を定期的に確認し、ユーザーが設定したルールに一致したファイルに対して、移動・名前変更・ZIP 化などの動作を自動で行う Windows 用の常駐ツール。「仕分け」に加えて、手動で実行する「クイック操作」によって、日常のファイル操作を効率化するパーソナルな効率化ソフトを目指す。

- 通知領域（タスクバー右下）に常駐し、指定間隔で自動実行する。
- ルールは条件（入れ子のグループ）と動作（複数ステップ）からなり、上から順に判定して最初に一致したルールを適用する。
- ルール設計を確かめるテスト機能（実ファイルでのシミュレーション、仮想ファイルでの判定、編集中の即時テスト）を備える。
- 処理結果は履歴に残り、「元に戻す」ことができる。

## 4. 起動方法・起動モード・配布形態

エントリポイントはソース版が `run.pyw`、exe 版が `FileSortKun.exe`（同じ引数を受け付ける）。

| 引数 | 動作 |
|---|---|
| （なし） | 常駐プロセスが未起動なら起動し、GUI を開く（通常の起動方法） |
| `--background` | 常駐プロセスのみ起動（自動起動で使用）。起動済みなら何もせず終了 |
| `--gui [--page X]` | GUI のみ。X = `home` / `rules` / `test` / `history` / `settings`。GUI が開いていれば前面に出して終了 |
| `--simulate` | コンソールに判定結果を表示（ファイルは動かさない。ソース版のみ） |
| `--run-once` | 1回だけ自動ルールを実行して結果を表示（ソース版のみ） |

- **自動起動**：設定画面でオンにすると `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` に値 `FileSortKun` を登録（ソース版 `"<pythonw.exe>" "<run.pyw>" --background`、exe 版 `"<FileSortKun.exe>" --background`）。常駐プロセスの起動時に、登録済みのコマンドが現在の場所と違えば書き換える（アプリのフォルダを移動しても自動起動が切れない）。
- **exe 版**：`tools/build_exe.ps1` が PyInstaller の onedir 形式で `dist\FileSortKun\` を作成し、`portable.txt`・README・LICENSE を同梱、配布用 ZIP（`dist\FileSortKun-vX.Y.Z-win64.zip`）も作る。onedir 形式のため常駐は単一プロセス（onefile のような展開用の親プロセスが無い）。アセットは `_internal\assets`（`sys._MEIPASS`）から読む。
- 環境変数 `FILESORTKUN_DATA` で設定・履歴の保存先を強制指定できる（テスト用、最優先）。

## 5. アーキテクチャ

```
┌──────────────────────── 常駐プロセス（--background）──────────────────────────────┐
│  メインスレッド: TrayIcon（Win32 メッセージループ）… クリック/メニュー/通知/ツールチップ │
│  スケジューラスレッド: WaitForMultipleObjects([終了, 再読込, 今すぐ実行, 変更通知…],  │
│                       タイムアウト=次回実行まで) → engine.run_once(progress=…)        │
└──────────────▲───────────────────────────────────────▲─────────────────────────────┘
               │ 名前付きイベント / request.json           │ state.json（状態・進捗）
┌──────────────┴──────── GUI プロセス（--gui）────────────┴────────────────────────────┐
│  tkinter + sv-ttk。開いている間だけ存在。閉じるとプロセスごと終了してメモリを解放      │
└──────────────────────────────────────────────────────────────────────────────────────┘
     共有ファイル（データフォルダ）: config.json / history.json / state.json / exclusions.json / request.json
```

### 5.1 プロセス間連携（IPC）

名前空間は `Local\`（同一ログオンセッション内）。`FileSortKun` は `filesorter.APP_ID`。

| 名前 | 種類 | 作成者 | 用途 |
|---|---|---|---|
| `Local\FileSortKun.Resident` | ミューテックス | 常駐 | 常駐の多重起動防止・生存確認 |
| `Local\FileSortKun.GUI` | ミューテックス | GUI | GUI の多重起動防止 |
| `Local\FileSortKun.RunLock` | ミューテックス | 両方 | 実行・元に戻す・履歴/除外リスト更新・保存先切替の排他（待機上限 120 秒） |
| `Local\FileSortKun.Reload` | 自動リセットイベント | 常駐 | 設定の再読込 |
| `Local\FileSortKun.RunNow` | 自動リセットイベント | 常駐 | 今すぐ実行。直前に `request.json` があればクイック操作（そのルールのみ実行） |
| `Local\FileSortKun.Quit` | 自動リセットイベント | 常駐 | 常駐プロセスの終了 |

- `request.json`：`{"rule_id": "...", "time": エポック秒}`。常駐が RunNow 受信時に読み出して削除する。60 秒より古い依頼は無視。
- 設定の保存は「最新の config.json を読み直す → 変更を適用 → 保存」（`config.update_config`）で行い、保存後に Reload をシグナルする。
- GUI は state.json とミューテックスを、通常 2 秒ごと、実行中は 0.3 秒ごとに確認する（GUI 表示中のみ）。
- 常駐がない状態で GUI から実行した場合は、GUI プロセス内のスレッドで実行する（同じ RunLock を使用）。

## 7. データ保存場所

保存先の優先順位：①環境変数 `FILESORTKUN_DATA` ②アプリフォルダに `portable.txt` があれば `<アプリフォルダ>\data`（ポータブルモード） ③`%APPDATA%\FileSortKun`。アプリフォルダはソース版がプロジェクトルート、exe 版が exe のあるフォルダ。

設定画面の「ポータブルモードにする／通常モードに戻す」で切り替える。切替時は現在のデータ（config / history / state / exclusions）を新しい保存先にコピーし、`portable.txt` を作成/削除して、常駐プロセスを再起動する。

書き込みはすべて一時ファイル → `os.replace` の原子的置換。

| ファイル | 内容 |
|---|---|
| `config.json` | 設定とルール（§8） |
| `history.json` | 処理履歴（§9.8） |
| `state.json` | 常駐プロセスの状態・進捗（§9.9） |
| `exclusions.json` | 再処理しないファイル（§9.7） |
| `request.json` | クイック操作の依頼（一時的） |
| `app.log` | ログ（512KB × 2 世代） |
| `config.v1.bak.json` | v1 から移行したときの元の設定 |
| `config.broken-*.json` | 読み込めなかった設定の退避 |

## 8. 設定・ルールの仕様（config.json, version 2）

### 8.1 全体設定

| キー | 型 | 既定値 | 範囲・説明 |
|---|---|---|---|
| `version` | int | 2 | 設定形式のバージョン |
| `enabled` | bool | true | false で自動実行を一時停止（手動実行・クイック操作は可能） |
| `watch_folders` | string[] | `["{downloads}"]` | 監視フォルダ。`{downloads}` は実行時にその PC のダウンロードフォルダ（レジストリ User Shell Folders）に置換。環境変数・`~` 可。相対パスはアプリフォルダ基準。v1 からの移行時、ダウンロードフォルダの絶対パスは `{downloads}` に変換 |
| `interval_sec` | int | 300 | 実行間隔（10〜86400 秒） |
| `settle_sec` | int | 30 | 待機時間（0〜3600 秒）。§9.1 |
| `watch_changes` | bool | false | フォルダ変更検知で即時実行（§10.2） |
| `ignore_patterns` | string[] | 下記 | 除外パターン（ワイルドカード、大文字小文字無視） |
| `skip_hidden` | bool | true | 隠し/システム属性のファイルを無視 |
| `notify` | bool | true | 処理時に通知 |
| `theme` | string | "system" | `system` / `light` / `dark` |
| `history_limit` | int | 1000 | 履歴の保存件数（50〜100000） |
| `categories` | object | 下記 | 「種類」条件と `{category}` の拡張子グループ（JSON を直接編集） |
| `rules` | Rule[] | サンプル（すべて無効） | §8.2 |

既定の除外パターン：`*.crdownload` `*.part` `*.partial` `*.download` `*.opdownload` `*.tmp` `*.temp` `*.!ut` `*.!qb` `*.aria2` `~$*` `.~lock.*` `desktop.ini` `thumbs.db`

既定のカテゴリ：`image` 画像 / `video` 動画 / `audio` 音声 / `document` 文書 / `archive` 圧縮ファイル / `installer` インストーラ / `code` コード / `font` フォント（拡張子は `config.DEFAULT_CATEGORIES`）

初回のサンプルルール：種類別の移動 6 件（インストーラ・画像・動画・音声・文書・圧縮ファイル）と、手動ルールの例「古いスクリーンショットを月ごとにZIP（例）」。**すべて無効状態**で作成する。

### 8.2 ルール（Rule）

| キー | 型 | 説明 |
|---|---|---|
| `id` | string | 一意 ID（`r` + 16進8桁） |
| `name` | string | ルール名（必須） |
| `enabled` | bool | 有効/無効（自動実行で使うか。クイック操作では無効でも実行できる） |
| `trigger` | `"auto"` / `"manual"` | 自動（定期実行・今すぐ仕分けの対象）/ 手動のみ（クイック操作でだけ実行） |
| `conditions` | Group | 条件のルートグループ（§8.3） |
| `actions` | Step[] | 動作（1件以上、上から順に実行。§9.2） |
| `folders` | string[] | 対象の監視フォルダ。**空（または項目なし）ならすべての監視フォルダ**。値は `watch_folders` に書かれた表記のまま保存する（`{downloads}`・相対パス等）。比較は両者を実際のパスに解決し、大文字小文字を無視して行う |

**対象フォルダの補足**
- `folders` に、`watch_folders` に存在しないフォルダが含まれていてもエラーにはしない（そのフォルダには適用されないだけ）。ルール一覧では対象フォルダ欄に ⚠ を付けて知らせる（`config.missing_rule_folders`）。
- 範囲が広がる事故を防ぐため、監視フォルダを外しても `folders` から自動で削除はしない（空になると「すべて」に変わってしまうため）。設定画面で、ルールが対象にしている監視フォルダを外すときは確認を出す。
- 「選択したフォルダのみ」でフォルダを1つも選んでいない場合は、保存時のエラーにする（GUI で検証）。

**v1 からの移行**：`conditions` がリストなら `{"type":"group","match":<旧match>,"items":[…]}` に、`action` / `destination` / `conflict` は `actions: [{"type":"move","target":destination,"conflict":conflict}]`（recycle / ignore はそのまま1ステップ）に変換する。旧形式の設定ファイルは `config.v1.bak.json` に残してから v2 で保存し直す。

### 8.3 条件（Group / Condition）

```json
{"type": "group", "match": "all | any", "negate": false, "items": [ Group | Condition, ... ]}
{"type": "cond", "field": "…", "op": "…", "value": "…", "value2": "", "unit": "", "negate": false}
```

- グループは `match`=`all`（すべて一致＝AND）/ `any`（いずれか一致＝OR）、`negate` で結果を反転。入れ子は最大 6 段。
- 空のグループは常に不一致（否定していても不一致）。条件が1つも無いルールは一致しない。

| field | 表示名 | op | 判定内容 |
|---|---|---|---|
| `name` | ファイル名（拡張子を含む） | `contains` / `startswith` / `endswith` / `equals` / `wildcard` / `regex` | 文字列比較（下記） |
| `stem` | ファイル名（拡張子を除く） | 同上 | 同上 |
| `url` | ダウンロード元URL | 同上 | Zone.Identifier の HostUrl / ReferrerUrl の**いずれか**が一致で真。情報が無ければ偽 |
| `ext` | 拡張子 | `in` | カンマ・空白・`;`・`|` 区切りの一覧。先頭の `.` 省略可。`tar.gz` のようなドット入りは末尾一致 |
| `category` | 種類 | `is` | `categories[value].exts` のいずれか |
| `size` | サイズ | `gte` / `lte` / `between`（両端含む、大小逆可） | `unit`: `B` `KB` `MB` `GB`（1024 進） |
| `mtime` | 更新日時 | `older`（N 以上前）/ `newer`（N 以内） | `unit`: `min` `hour` `day` |
| `ctime` | 作成日時（ダウンロード日時） | 同上 | 同上 |
| `all` | すべてのファイル | `always` | 常に真 |

文字列条件：大文字・小文字を区別しない。`regex` 以外は `|` 区切りで複数候補（いずれかに一致）。`wildcard` は fnmatch（全体一致）。`regex` は Python `re`（IGNORECASE、部分一致）。判定時のエラー（正規表現・数値の不正）はその条件を常に不一致とし、保存時は `rules.validate_rule` でエラーを表示して保存させない。

### 8.4 判定の流れ

1. 自動実行では `trigger=auto` かつ有効なルールを、上から順に評価する（クイック操作では指定した1ルールのみ）。監視フォルダごとに、そのフォルダを対象にするルール（`folders` が空か、そのフォルダを含むもの）だけに絞ってから評価する（`engine.rules_for_folder`）。
2. 条件ツリーを評価する（本番は短絡評価、テスト表示は全評価してツリーで表示）。
3. **最初に一致したルールのみ**を適用し、以降のルールは評価しない。
4. 「何もしない（除外）」を含むルールに一致したファイルは何もせず、以降のルールも適用しない。

## 9. 動作（actions）と処理の仕様

### 9.1 スキャン対象

- 監視フォルダの**直下のファイルのみ**（サブフォルダ・シンボリックリンクは対象外）。
- 次のファイルはルール判定前にスキップ（この順）：除外パターン → 隠し/システム属性 → 待機時間内（`現在 − max(更新日時, 作成日時) < settle_sec`）→ 除外リスト（§9.7。クイック操作では「元に戻した」もののみ対象外）。

### 9.2 ステップの種類

```json
{"type": "move|copy|rename|zip|extract|recycle|command|ignore", "target": "…", "conflict": "rename|overwrite|skip", "remove_original": true}
```

| type | target | その他 | 処理 |
|---|---|---|---|
| `move` | 移動先フォルダ | conflict | フォルダを作成して移動。移動先が元と同じなら何もしない |
| `copy` | コピー先フォルダ | conflict | コピー（元は残る） |
| `rename` | 新しい名前（拡張子込み） | conflict | 同じフォルダ内で名前を変更。`\` `/` は使用不可、禁止文字は `_` に置換 |
| `zip` | ZIP ファイルのパス（`.zip` は自動付与） | remove_original（既定 true） | 既存の ZIP には追記。ZIP 内に同名があれば `名前 (1).拡張子`。圧縮済み形式（jpg/mp4/zip/docx 等）は無圧縮で格納し CPU を節約。追加後に元をごみ箱へ（設定時）。**保存先が監視フォルダ直下の場合はエラー**（ZIP 自体が再処理されるのを防ぐ） |
| `extract` | 展開先フォルダ（既定 `{stem}`） | remove_original（既定 false） | ZIP 形式のみ。ファイル名は cp932 → 失敗時は標準の文字コードで解釈。ZIP 外を指すパス（Zip Slip）は無視。既存ファイルとは連番で共存。展開後に元の ZIP をごみ箱へ（設定時） |
| `recycle` | — | — | ごみ箱へ（完全削除はしない。ごみ箱が使えないドライブでは確認ダイアログ） |
| `command` | コマンドライン | — | `CreateProcess` で実行（シェル経由ではない。シェル機能が必要なら `cmd /c …`）。ウィンドウ非表示、最大 300 秒、終了コード 0 以外はエラー。実行後にファイルが無くなっていればそこで終了 |
| `ignore` | — | — | 何もしない（他の動作と組み合わせ不可） |

- ステップは上から順に実行し、各ステップは直前のステップ後のファイルを対象にする（例：名前変更 → 移動）。
- ファイルが無くなるステップ（`recycle`、`remove_original` 付きの `zip` / `extract`、`ignore`）の後ろには動作を置けない（検証エラー）。
- 途中でエラーが起きた場合は以降のステップを行わず、それまでの結果を履歴に残す。使用中のファイルはエラーとして次回再試行。

### 9.3 パスと差し込み

- フォルダ/ファイルの指定は絶対パス、または**監視フォルダからの相対パス**。環境変数・`~` 可。
- 差し込み（値中のファイル名禁止文字は `_` に置換、未知の `{xxx}` はそのまま）：

| 記法 | 値 |
|---|---|
| `{name}` `{stem}` `{ext}` | その時点のファイル名（拡張子込み）/ 拡張子なし / 拡張子（小文字、無ければ「拡張子なし」） |
| `{category}` | 種類の表示名（無ければ「その他」） |
| `{yyyy}` `{mm}` `{dd}` | 更新日時の年・月・日 |
| `{cyyyy}` `{cmm}` `{cdd}` | 作成日時（ダウンロード日時）の年・月・日 |
| `{today}` | 実行日（YYYY-MM-DD） |
| `{host}` | ダウンロード元ドメイン（ReferrerUrl 優先、`www.` 除去。無ければ「不明」） |
| `{rule}` | ルール名 |
| `{path}` `{dir}` | **コマンドのみ**：ファイルのフルパス / フォルダ（加工せずに展開） |

### 9.4 移動の方法

同一ドライブは `os.rename`（代替データストリームも保持）。別ドライブはコピー後に元を削除し、**元の削除に失敗した場合はコピーを削除して中断**（重複を作らない）。

### 9.5 同名ファイル（conflict）

`rename`：`名前 (1).拡張子` … と空いている名前 / `overwrite`：既存をごみ箱へ送ってから処理 / `skip`：処理しない（以降のステップも行わない。次回再判定）。

### 9.6 元に戻す

履歴1件ごとに、記録したステップを**逆順に取り消す**。

| ステップ | 取り消し |
|---|---|
| move / rename | 移動先から元のパスへ戻す（同名があれば連番） |
| copy | コピーをごみ箱へ |
| zip | 元をごみ箱へ送っていた場合は ZIP から元の場所へ取り出す（ZIP 内のファイルは残る） |
| extract | 展開で新規作成したフォルダをごみ箱へ（元の ZIP をごみ箱へ送っていた場合は手動で復元） |
| recycle / command | 取り消せない（ごみ箱から手動復元 / 補足として表示） |

元の場所に戻ったファイルは除外リスト（理由 `undone`）に登録し、再処理しない。

### 9.7 除外リスト（exclusions.json）

`{ "<正規化パス>": {"size": n, "mtime": t, "reason": "undone | processed"} }`

- `undone`：元に戻したファイル。
- `processed`：処理後も監視フォルダ直下に残ったファイル（コピーのみ・名前変更のみ・元を残す ZIP 化・コマンド等）。同じ内容のまま繰り返し処理しないため。
- サイズか更新日時が変わると対象外（再び処理対象）。存在しないエントリは実行時に削除。設定画面で理由ごとにリセットできる。

### 9.8 履歴（history.json）

```json
{"id": "16進12桁", "time": 1793987511.1, "name": "a.pdf", "src": "元のパス", "rule": "ルール名", "rule_id": "r…",
 "size": 123, "steps": [{"type": "rename", "from": "…", "to": "…", "replaced": false},
                        {"type": "zip", "from": "…", "archive": "…", "entry": "…", "removed": true}, …],
 "final": "処理後のパス（無くなった場合は空）", "error": "", "skipped": "", "undone": false,
 "undone_time": 0, "restored_to": "元に戻した先"}
```

v1 形式（`action` / `src` / `dst`）の履歴も表示・元に戻すに対応する。

### 9.9 状態（state.json）

常駐プロセスが書き出す：`pid`、`started`、`paused`、`next_run`、`running`（実行中か）、`progress`（`done` / `total` / `current`（処理中のファイル名）/ `rule`（クイック操作のルール名）/ `started`）、`run_seq`（実行完了ごとに +1）、`last_run`、`last_result`（`done` / `errors` / `skipped` / `error_messages` / `rule` / `manual` / `seconds`）、`last_error`、`updated`。進捗は最大 0.25 秒間隔で書き出す。

## 10. スケジューリング仕様

### 10.1 定期実行
起動 5 秒後に初回、以後 `interval_sec` ごと。待機は `WaitForMultipleObjects`（CPU 使用なし）。一時停止中は無期限待機し、再開から約 2 秒後に実行。間隔が短くなった場合は次回時刻を前倒しする。

### 10.2 変更検知（`watch_changes`）
`FindFirstChangeNotificationW`（ファイル名の変更、サブフォルダ対象外）を待機対象に加え、変更から「待機時間 + 2 秒」後に実行を予約（連続変更で延長）。実行後に通知ハンドルを作り直し、自分の処理による通知を捨てる。

### 10.3 手動実行・クイック操作
| イベント | 動作 |
|---|---|
| 今すぐ仕分け（トレイ / GUI） | 最新設定で自動ルールを即時実行（一時停止中でも実行）。次回の定期実行はそこから `interval_sec` 後 |
| クイック操作（トレイのサブメニュー / ホーム画面 / ルール画面「選択したルールを今すぐ実行」） | 指定ルールのみを実行（手動・無効でも実行、`processed` の除外は無視）。定期実行の予定は変えない |
| 設定の再読込 / 終了 | config.json の再読込と通知ハンドルの再作成 / スケジューラ停止・トレイ削除・終了 |

### 10.4 実行中の表示と完了検知
- GUI は依頼時の `run_seq` を覚え、state.json の `run_seq` が増えて `running=false` になったら完了とみなし、`last_result` をトーストで表示（件数・所要時間・エラー件数と先頭のエラー）。
- 実行中は右下の進捗パネル（「仕分け中… 4 / 11」・進捗バー・処理中のファイル名・経過秒）を表示し、実行系ボタン（今すぐ仕分け・クイック操作・選択ルールの実行）を無効化する。定期実行による処理中も同様に表示する。
- 常駐が途中で終了した場合や 300 秒応答が無い場合はエラーとして終了扱いにする。
- トレイのツールチップも実行中は「仕分け中…」になり、メニューの実行項目は無効になる。

## 13. 軽量化の設計

- 常駐プロセスはサードパーティ製ライブラリ・tkinter を読み込まない。トレイは Win32 API を ctypes で直接利用。
- 待機は OS の待機関数（ポーリングしない）。進捗の書き出しは 0.25 秒以上の間隔に間引く。
- スキャンは直下のみ、URL（代替データストリーム）は URL 条件の評価時だけ読む。正規表現はキャッシュ。ZIP 化では圧縮済み形式を再圧縮しない。
- GUI は必要なときだけ別プロセスで起動し、閉じると完全に解放。実行中以外のポーリングは 2 秒間隔。
- 実測（Windows 11、2026-11-08）：

| プロセス | ワーキングセット | プライベート |
|---|---|---|
| 常駐（ソース版 / exe 版） | 約 27 MB / 約 28 MB | 約 15 MB / 約 17 MB |
| GUI（表示中のみ） | 約 50 MB | 約 26 MB |
| exe 版の配布サイズ | 約 26 MB（フォルダ） | — |

## 14. 安全設計

- 完全削除は行わない（ごみ箱・上書き時の既存ファイル・ZIP 化後の元ファイルもごみ箱へ）。
- サンプルルールは無効状態で作成。インポートしたルールにコマンド実行が含まれる場合は警告して無効状態で追加。
- 待機時間・除外パターンでダウンロード中/コピー中のファイルを保護。使用中ファイルは触らず次回再試行。
- 別ドライブ移動の失敗時はコピーを消して重複を防止。ZIP の保存先を監視フォルダ直下に置けない。ZIP 展開時は Zip Slip を無視。
- 履歴から元に戻せる。戻したファイルは再処理しない。処理済みファイルも内容が変わるまで再処理しない。
- 設定ファイルが壊れていれば退避して既定値で起動。v1 設定は移行前の内容をバックアップ。

4. 設定形式を変更する場合は `config.CONFIG_VERSION` を上げ、`normalize_config` / `normalize_rule` で旧形式を読み替える。
